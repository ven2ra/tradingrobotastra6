# MOEX Multi-strategy terminal

React/TypeScript/Tailwind терминал с восемью экранами, реальными котировками T-Invest и отдельным paper-движком. Монитор получает данные; торговые решения и отправка paper-заявок принадлежат backend. [Архитектура и стратегии](docs/design.md).

## Интерфейс

```powershell
cd frontend
npm ci
npm run dev
```

Открыть http://127.0.0.1:5186. По умолчанию выбран T-Invest. Переключатель источника также предлагает отдельные Paper API и демонстрационный портфель. UI никогда не подставляет демо-данные при ошибке реального API.

Конструктор всех восьми классов и риск-политика проверяют JSON Schema, сохраняют локальные черновики и экспортируют JSON. Черновики **не активируют** стратегию. Журнал имеет поиск, фильтры и экспорт; Watchlist сохраняется в браузере. Live показывает предупреждение и блокировку запуска.

## T-Invest

Скопировать `.env.example` в `.env`, указать `T_INVEST_TOKEN` только на сервере. Для котировок достаточно токена с доступом на чтение; браузер токен не получает. `.env` исключён из Git и Docker build context. При компрометации токен необходимо отозвать у брокера.

`T_INVEST_INSTRUMENTS` задаёт `TICKER_BOARD` через запятую; пустое значение включает поиск до `T_INVEST_MAX_INSTRUMENTS` ликвидных инструментов (максимум 300). Полный проход по большому списку дольше интервала опроса: лимит запросов ограничен, одновременно обрабатывается не более трёх инструментов. UI показывает время каждой цены; устаревшая котировка или стакан переводят режим в UNDEFINED. `T_INVEST_POLL_SECONDS` — пауза между завершёнными проходами, а не гарантия обновления всех 300 бумаг каждые 15 секунд.

Watchlist автоматически пополняется ликвидным каталогом T-Invest: ориентир — 100 акций и 200 облигаций, с заполнением свободных мест другим классом, если одного недостаточно. Отбор: RUB, основные доски MOEX, `liquidityFlag=true`, доступ через API. Это признак ликвидности брокера, не рейтинг по текущему обороту. Весь каталог отображается сразу, стартовые цены загружаются пакетным запросом. Удаления пользователя сохраняются, поиск и фильтр класса актива работают по всему списку. Если сервер ранее был ограничен четырьмя тикерами, очистить `T_INVEST_INSTRUMENTS` в его `.env` и перезапустить backend. Проверка реального каталога: `python backend/check_universe.py`.

Все адаптеры (`backend/tinvest.py` для котировок, `backend/live.py` для чтения счёта, `backend/live_orders.py` для реальных заявок) используют только явно разрешённые методы своего собственного allowlist и проверяют TLS с отдельным CA для T-Invest. `tinvest.py` и `live.py` физически не способны вызвать OrdersService — этого метода просто нет в их allowlist. Единственное место в кодовой базе, где вообще есть вызовы OrdersService, — `live_orders.py`, и там заявка уходит брокеру только из `approve_proposal()`, вызываемой исключительно по явному действию администратора. Сертификат: [официальная инструкция T-Bank](https://developer.tbank.ru/invest/intro/developer/network), источник PEM — `https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt`. Системное хранилище доверия не меняется.

Часовые SMA50, ATR14, ADX14, RSI14 и 20-барный диапазон рассчитываются на завершённых свечах. SIGNAL в журнале — кандидат, **не ордер**. Для исполнения не подключены портфель, календарь событий и полная политика риска реального счёта. Облигационные входы запрещены, пока отсутствуют проверенные YTM/дюрация/рейтинг/календарь. В выходные и при закрытой сессии входы запрещены.

## Live

**Фаза 1 · счёт (только чтение).** Диалог Live на шаге 2 показывает реальный брокерский счёт: `GET /api/live/account` вызывает `UsersService.GetAccounts` и `OperationsService.GetPortfolio` (нужен токен с доступом к счёту — это отдельная опция при выпуске токена, не совпадает с правами на котировки). Каждая попытка активации пишется в audit-журнал (`GET /api/live/audit`).

**Фаза 2 · реальные заявки, только с ручным подтверждением.** Пока Live не взведён администратором (`POST /api/live/armed`, требует `ADMIN_PASSWORD`), сигналы стратегий из `tinvest.py` остаются просто записями в журнале, как раньше. После взвода тот же сигнал (реальный, посчитанный по реальным котировкам и индикаторам) дополнительно создаёт предложение в локальном хранилище (`backend/live_orders.py`, SQLite) — заявка при этом **не уходит брокеру**. Отправка происходит только когда администратор в разделе «Настройки T-Invest → Live» нажимает «Отправить» по конкретному предложению (`POST /api/live/orders/{id}/approve`); «Отклонить» просто помечает его REJECTED без единого сетевого вызова. Предложение протухает и снимается с подтверждения через 3 минуты (цена сигнала могла уйти). Kill-switch (`POST /api/live/kill`) снимает взвод и отменяет все ещё висящие на бирже заявки, отправленные этим приложением; открытые позиции он не закрывает — это было бы уже автономной сделкой. При старте backend сверяет локально «отправленные» заявки с `OrdersService.GetOrders` брокера (`live_orders.reconcile`), чтобы не потерять их статус после перезапуска контейнера.

Полностью автономная (без подтверждения) отправка заявок сознательно не реализована.

Токен, ID счёта для торговли и лимит инструментов можно менять из интерфейса («Настройки T-Invest» в сайдбаре) без пересборки контейнера — форма и все `/api/live/*`-эндпоинты, кроме чтения счёта, защищены паролем `ADMIN_PASSWORD` из `.env`; если переменная не задана, форма отключена. Смена токена «горячо» пересоздаёт наблюдателя котировок и клиент счёта.

## Состав

- `schemas/strategy.schema.json`: JSON Schema 2020-12 для всех восьми классов, включая Event и RiskOff как надстройки.
- `schemas/risk-policy.schema.json`: общая обязательная политика риска.
- `docs/design.md`: матрица режимов, архитектура, UI, дизайн-токены, Live-протокол, особенности облигаций.
- `backend/engine.py`: Decimal-расчёты, RiskEngine, интерфейс Strategy, четыре базовых плагина, paper-брокер и mock ticks.
- `backend/test_engine.py`: тесты риск-инвариантов и облигационного P/L.
- `backend/app.py`: FastAPI с backend-owned такт-циклом и read-only монитором.

## Запуск

Python 3.11+; команды из корня репозитория:

```powershell
python -m unittest discover -s backend -v
python backend/engine.py
python -m pip install -r backend/requirements.txt
python -m uvicorn app:app --app-dir backend --host 127.0.0.1 --port 8000 --workers 1
```

При установленном `uv`, если Python отсутствует в PATH:

```powershell
uv run --no-project python -m unittest discover -s backend -v
uv run --no-project --with-requirements backend/requirements.txt python -m uvicorn app:app --app-dir backend --host 127.0.0.1 --port 8000 --workers 1
```

API: `GET /api/paper/snapshot`, `GET /api/paper/journal`, Swagger `/docs`.
T-Invest: `GET /api/t-invest/snapshot`, `GET /api/t-invest/journal`. Состояние службы: `GET /api/health`.
`POST /api/live/arm` всегда возвращает 409: реального адаптера в примере нет.

Проверка схем и API:

```powershell
uv run --no-project --with-requirements backend/requirements.txt python backend/check_contracts.py
uv run --no-project --with-requirements backend/requirements.txt python -m unittest discover -s backend -v
cd frontend
npm run build
npm run test:e2e
```

Backend-тесты покрывают риск-инварианты, облигационный P/L, классификатор, неполные свечи, ошибки авторизации, 429/backoff, пустые ответы и старение котировок. Контрактные тесты никогда не используют реальный токен. Playwright проверяет экраны, конструкторы, сохранение, мобильную компоновку, Live-блокировку и потерю API. На Windows используется Edge; в Linux предварительно выполнить `npx playwright install --with-deps chromium`.

## Границы реализации

Интерфейс реализован; торговое ядро остаётся paper reference. Полные параметры всех стратегий представлены в схемах; четыре Python-плагина демонстрируют базовые сигналы. Breakout и Momentum не исполняются этим примером. Календарный запрет и Risk-off исполняются в RiskEngine.

PaperBroker исполняет заявку целиком при пересечении лимита, немедленно подтверждает отмену и не моделирует очередь, частичные сделки, биржевые ценовые коридоры, задержку или маржинальное обеспечение. Grid исполняет один уровень без дозаполнения позиции; пирамидинг отключён. Уровни N-bar/MA/ATR/ADX/RSI и облигационные метрики приходят с mock tick, а не вычисляются из истории. Конструкторская схема является контрактом полной системы, а не обещанием поддержки всех параметров демо-движком.

Состояние демо хранится в памяти; перезапуск сбрасывает портфель. Live должен сохранять дневной стоп, резервы, ownership и журнал транзакционно и восстанавливаться через сверку с брокером; архитектура описана в проекте. Купон и амортизация учитываются функцией total-return P/L; демо-цикл не имитирует календарь выплат. Недельная просадка в демо отсчитывается от переданного `week_peak`; недельный календарный rollover не имитируется.

Live умеет выставлять реальные заявки, но только по одной, вручную, после явного взвода администратором и подтверждения каждого конкретного предложения — полностью автономного исполнения нет и оно не планируется без отдельного пересмотра рисков. Предложения создают те же три плагина (Grid/Trend/MeanReversion), что и в paper-режиме, с их дефолтными настройками — то есть каждое предложение всегда на 1 лот; `RiskEngine` из paper-движка их не проверяет и никаких лимитов на сумму/число одобренных заявок нет — единственный риск-контроль сейчас это сам администратор, читающий предложение перед нажатием «Отправить». Хранилище предложений — SQLite, не полноценная транзакционная база; сверка с брокером при старте (`GetOrders`) best-effort и не восстанавливает частично исполненные заявки. Kill-switch отменяет висящие заявки, но не закрывает уже открытые позиции.

Не является индивидуальной инвестиционной рекомендацией. Торговля связана с риском потери капитала.
